# سامانه مربی‌گری تندرستی

وب‌سایت فارسی راست‌چین برای معرفی خدمات مربی تمرین و تغذیه، ثبت درخواست مراجعان، پرداخت زیبال و مدیریت سفارش‌ها.

## فناوری‌ها

- Next.js App Router، TypeScript و Tailwind CSS
- PostgreSQL و Prisma ORM 7 با آداپتر رسمی PostgreSQL `@prisma/adapter-pg`
- Zod برای اعتبارسنجی سمت سرور
- Recharts برای نمودارهای پنل مدیر
- Kavenegar Verify Lookup برای ورود با کد یک‌بارمصرف
- Zibal IPG برای پرداخت

## راه‌اندازی محلی

### ورود مدیر و پنل توسعه

در `.env.local` مقدار `ADMIN_PHONE="09xxxxxxxxx"` را روی شماره مالک بگذارید. پس از اجرای مهاجرت‌ها و `npm run dev`، از صفحه ورود دکمه «ورود مدیر برای تست محلی» فقط روی همین رایانه در دسترس است؛ این دکمه فقط در حالت توسعه ساخته می‌شود. برای ارتقای حساب موجود با پیامک، می‌توانید `npm run admin:provision -- 09xxxxxxxxx` را اجرا کنید. در محیط واقعی، ورود عادی با OTP انجام می‌شود و همان شماره باید در `ADMIN_PHONE` تنظیم شده باشد.

پنل `/admin` درآمد و تعداد پرداخت‌های موفق هفتگی، ماهانه و سالانه و تعداد بازدید صفحه‌ها را نشان می‌دهد. آمار بازدید فقط مسیر و زمان صفحه را ذخیره می‌کند و IP یا اطلاعات شناسایی بازدیدکننده را نگه نمی‌دارد. مهاجرت `20261115050000_site_visits` باید روی دیتابیس اجرا شود.

نیازمندی‌ها: Node.js 20 یا جدیدتر و PostgreSQL.

1. وابستگی‌ها را نصب کنید: `npm install`
2. فایل `.env.example` را به `.env` کپی کنید و مقادیر لازم را تنظیم کنید.
3. Prisma Client را بسازید: `npm run prisma:generate`.
4. یک پایگاه PostgreSQL بسازید و `DATABASE_URL` را در `.env` قرار دهید.
5. مهاجرت توسعه را اجرا کنید: `npm run db:dev -- --name init`
6. بسته‌های نمونه را وارد کنید: `npm run db:seed`
7. سرور را اجرا کنید: `npm run dev`

برای محیطی که مهاجرت‌ها از قبل ساخته شده‌اند از `npm run db:migrate` استفاده کنید. این فرمان `prisma migrate deploy` است و با پایگاه خالی، ابتدا مهاجرت توسعه را بسازید یا مهاجرت موجود را اعمال کنید.

## متغیرهای محیطی

علاوه بر `SESSION_SECRET`، مقدار `HEALTH_DATA_KEY` باید Base64 یک کلید تصادفی ۳۲ بایتی باشد. برای ساخت هر کلید، جداگانه از `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"` استفاده کنید. پاسخ‌های سلامت با AES-256-GCM در پایگاه رمز می‌شوند. کلید را جدا از پایگاه و نسخه پشتیبان امن نگه دارید؛ با گم‌شدن آن، پاسخ‌های رمز‌شده بازیابی نمی‌شوند.

| متغیر | کاربرد |
| --- | --- |
| `DATABASE_URL` | نشانی PostgreSQL |
| `SESSION_SECRET` | راز حداقل ۳۲ نویسه برای هش کد و نشست |
| `NEXT_PUBLIC_SITE_URL` | نشانی اصلی سایت برای callback و SEO |
| `NEXT_PUBLIC_BRAND_NAME` | نام قابل تنظیم مجموعه |
| `COACH_NAME`، `COACH_BIO`، `COACH_QUALIFICATIONS` | نام، معرفی و صلاحیت‌های مربی |
| `NEXT_PUBLIC_CONTACT_PHONE`، `NEXT_PUBLIC_CONTACT_EMAIL`، `NEXT_PUBLIC_INSTAGRAM_URL` | راه‌های تماس قابل نمایش |
| `KAVENEGAR_API_KEY` | کلید فقط سمت سرور کاوه‌نگار |
| `KAVENEGAR_OTP_TEMPLATE` | نام قالب Verify Lookup که متغیر `token` را می‌پذیرد |
| `ZIBAL_MERCHANT` | شناسه پذیرنده زیبال؛ `zibal` برای آزمون، شناسه واقعی برای فروش |
| `SEED_NUTRITION_PRICE_RIALS`، `SEED_TRAINING_PRICE_RIALS`، `SEED_COMBINED_PRICE_RIALS` | قیمت بسته‌های نمونه به ریال |

نام، اطلاعات تماس و معرفی پیش‌فرض واقعی نیستند؛ مقادیر کسب‌وکار باید قبل از انتشار از محیط پیکربندی شوند. قیمت‌های seed صرفاً نمونه‌اند و می‌توان آن‌ها را از پنل مدیریت تغییر داد. Seed فقط بسته‌های غایب را ایجاد می‌کند و اجرای مجدد، بسته‌های موجود را بازنویسی نمی‌کند.

## مدیر نخست

پس از اجرای مهاجرت، شماره مدیر را در محیط سرور با فرمان زیر ارتقا دهید:

```sh
npm run admin:provision -- 09123456789
```

این ابزار فقط در محیط سرور اجرا می‌شود و شماره را به نقش مدیر ارتقا می‌دهد. فرم ثبت‌نام عمومی امکان انتخاب نقش مدیر را ندارد. سپس مدیر با همان شماره از جریان OTP وارد می‌شود.

## ورود پیامکی و پرداخت

سرویس پیامک باید در Kavenegar یک قالب Verify Lookup فعال داشته باشد که کد ورودی `token` را نمایش دهد. کد OTP در پایگاه فقط به‌صورت HMAC ذخیره می‌شود، پنج دقیقه اعتبار دارد، حداکثر پنج بار قابل بررسی است و ارسال مجدد و درخواست‌های هر شماره محدود شده‌اند. محدودسازی بر اساس شماره در پایگاه انجام می‌شود؛ در انتشار عمومی، محدودیت درخواست IP را نیز در لایه پراکسی یا WAF تنظیم کنید.

پرداخت در سمت سرور با `POST https://gateway.zibal.ir/v1/request` آغاز می‌شود و پس از بازگشت، با `POST https://gateway.zibal.ir/v1/verify` بررسی می‌شود. `trackId` نگهداری و نتیجه بررسی با مبلغ ذخیره‌شده مقایسه می‌شود؛ پاسخ مرورگر به تنهایی پرداخت را تأیید نمی‌کند. مبالغ بسته‌ها و تراکنش‌ها به **ریال** ذخیره می‌شوند. callback تکراری با به‌روزرسانی شرطی وضعیت پردازش می‌شود و برای جلوگیری از دو پرداخت هم‌زمان، درخواست سفارش هنگام رزرو پرداخت در PostgreSQL قفل می‌شود.

برای آزمون زیبال از شناسه پذیرنده آزمایشی `zibal` استفاده کنید؛ راهنمای فعلی اتصال و کارت‌های آزمایشی را در مستندات زیبال بررسی کنید. برای انتشار، شناسه پذیرنده واقعی را جایگزین کنید. ورود پیامکی و پرداخت واقعی بدون اعتبارنامه‌های Kavenegar و Zibal قابل آزمون کامل نیستند. منابع فنی: [مستندات درگاه زیبال](https://help.zibal.ir/IPG/API/) و [SDK رسمی Node.js زیبال](https://github.com/zibalco/gateway-nodejs). نمونه SDK رسمی مسیرهای درخواست، شروع پرداخت و verify و شکل فیلدهای `trackId` و `result` را نشان می‌دهد.

## فایل برنامه‌ها

فایل‌های تحویلی فقط PDF و حداکثر ۱۰ مگابایت هستند، با امضای PDF بررسی می‌شوند و با شناسه تصادفی در `.data/plans` ذخیره می‌شوند. دانلود از API محافظت‌شده عبور می‌کند و مالکیت درخواست و پرداخت تأییدشده را بررسی می‌کند. این مسیر به فضای ذخیره‌سازی پایدار نیاز دارد؛ هنگام استقرار روی محیط بدون دیسک پایدار، لایه ذخیره‌سازی را به مخزن خصوصی مانند S3 سازگار منتقل کنید و همین کنترل دسترسی را حفظ کنید. فایل‌های `.data` را در دسترس وب‌سرور عمومی قرار ندهید.

## فرمان‌های پروژه

- `npm run dev` اجرای توسعه
- `npm run lint` بررسی ESLint
- `npm run typecheck` بررسی TypeScript
- `npm test` اجرای آزمون‌های سیاست OTP، مجوزها، اعتبارسنجی فرم، منطق پرداخت و مرزهای زمانی تهران
- `npm run db:dev -- --name <نام>` ساخت مهاجرت توسعه
- `npm run db:migrate` اعمال مهاجرت‌های ثبت‌شده
- `npm run db:seed` ایجاد بسته‌های نمونه

آزمون‌های واحد در `src/lib/policies.test.ts` بدون دسترسی درگاه اجرا می‌شوند. برای آزمون انتهابه‌انتها، PostgreSQL و حساب آزمایشی زیبال لازم است؛ ارسال پیامک به کلید و قالب واقعی Kavenegar وابسته است.

## انتشار و حریم خصوصی

برنامه را روی Node.js با PostgreSQL اجرا کنید. پیش از انتشار، `SESSION_SECRET` تصادفی و قوی، `NEXT_PUBLIC_SITE_URL` عمومی، اطلاعات واقعی برند و قیمت‌ها را تنظیم کنید. TLS را در پراکسی فعال کنید، محدودیت نرخ IP برای APIهای OTP و تماس اضافه کنید و مسیر `.data/plans` را خصوصی نگه دارید. داشبوردها و داده‌های شخصی با `noindex` و robots از نمایه‌سازی کنار گذاشته شده‌اند.

حداقل‌سازی و حذف داده سلامت باید مطابق مدت نگهداری واقعی مجموعه انجام شود. متن صفحه حریم خصوصی و شرایط استفاده الگوی اولیه است؛ سیاست بازپرداخت، حذف و نگهداری را با روندهای واقعی کسب‌وکار هماهنگ و قبل از ارائه عمومی تکمیل کنید. سامانه تشخیص یا درمان پزشکی ارائه نمی‌کند.
